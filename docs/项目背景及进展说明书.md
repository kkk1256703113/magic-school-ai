## 📋 项目核心目标

### 🎯 使命愿景

**EduVisualizer 2.0** 是一个**专业的文档与学术公式可视化平台**，致力于：

- **让复杂文档内容变得直观易懂** - 通过AI驱动的可视化技术，将各种格式文档（PDF、Word、Markdown等）转换为精美的HTML作品集和交互式内容
- **让学术公式生动可视** - 智能识别和渲染LaTeX公式、数学表达式，生成专业的图表和动态演示
- **服务多元化用户需求** - 为职场人群提供报告可视化解决方案，为教育学生群体提供学习辅助工具

**核心问题解决**：
针对用户反馈"上传文件后，网站返回的是代码，而不是可视化页面"的关键问题，新增专门的HTML内容处理机制

**技术架构**：
```typescript
// src/utils/contentAnalysis.ts - HTML内容清理与处理
export const cleanAndRenderHTML = (htmlContent: string): string => {
  // 1. 移除不安全的脚本标签
  let cleaned = htmlContent.replace(/<script\b[^<]*(?:(?!<\/script>)<[^<]*)*<\/script>/gi, '')
  
  // 2. 清理潜在的安全风险元素
  cleaned = cleaned.replace(/<(iframe|object|embed|form)[^>]*>/gi, '')
  
  // 3. 保留核心的HTML结构和样式
  cleaned = cleaned.replace(/style\s*=\s*["'][^"']*["']/gi, (match) => {
    return match.replace(/javascript:/gi, '')
  })
  
  return cleaned
}
```

**智能渲染机制**：
- **内容类型检测** - 自动识别HTML、Markdown、纯文本格式
- **安全性过滤** - 移除潜在恶意代码，保留可视化内容
- **样式保留** - 确保数学公式、图表、表格正常显示
- **响应式适配** - 自动适配不同屏幕尺寸

**实现特色**：

## 🔍 经验教训与反思

### ✅ 成功经验

1. **模块化重构策略有效** - 单一职责原则大幅提升代码质量和维护性
2. **用户反馈驱动优化** - 直接解决实际使用痛点比盲目技术优化更有价值
3. **渐进式优化方式** - 分阶段解决问题，避免引入新的复杂性
4. **文档驱动开发** - 详细记录帮助发现根本问题，指导优化方向
5. **双AI模型策略** - 不同模型的优势互补，提供更好的用户体验
6. **成本控制意识** - 及时建立用户系统防止API滥用，控制运营成本
7. **前后端分离架构** - 提高系统可维护性和可扩展性

### ⚠️ 需要注意的教训

1. **技术实现 vs 产品定位** - 不能只关注技术指标，更要考虑用户实际需求
2. **避免过度工程化** - 技术要服务于教育目标，而不是为了技术而技术
3. **AI集成的人性化** - AI不仅仅是API调用，交互方式同样重要
4. **持续测试的重要性** - 重构后需要全面测试确保功能完整性
5. **成本预估的重要性** - API调用成本需要提前评估和控制
6. **安全第一原则** - 用户数据和密码安全必须优先考虑
7. **用户体验无小事** - 看似细微的交互细节会影响整体学习体验

### 💭 深度思考启发

1. **产品思维的重要性** - 始终以用户价值为导向，技术服务于教育目标
2. **教育工具的独特性** - 与一般的技术产品不同，需要温度和启发性
3. **AI时代的人文关怀** - 技术越先进，越需要人性化的交互设计
4. **持续迭代的必要性** - 教育需求在变化，工具也需要持续进化
5. **团队协作的价值** - 好的文档和规划让团队协作更高效
